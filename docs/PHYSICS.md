# Native MuJoCo physics

Jester uses the official **MuJoCo 3.3.7** native C API, dynamically linked. Qt Widgets provides the interface; O3DE Atom renders the viewport through DX12. Normal use needs neither Python, GPU compute, nor a separate physics server. This is an experimental animation tool, not an equivalent of Cascadeur/AutoPhysics.

## Workflow

1. Open a character, review Profile and choose the interval in Physics.
2. **Model** checks compilation and displays mass/COM; edit capsule/foot dimensions and orientation, local COM, principal inertia/orientation and per-body drive settings. Add/remove bodies, Fit human rig and Fit feet are explicit undoable operations. The human preset uses estimated segment fractions; it is not a measurement. Zero inertia selects a documented estimate; -1 drive values inherit the world settings. Export MJCF to inspect the portable generated model.
3. Set authored contacts and important frames. The green/purple timeline band is the authored contact/flight schedule, not a contact measurement. Fade-in/out is a transition; fully planted errors are distinguished from transition errors.
4. **Pose** (also Ctrl+Shift+W) solves multiple hard/soft weighted targets and optional COM projection. It creates/uses the selected correction layer and writes one pose key per Solve + key, with one Undo. Hard priorities use large penalty weights; conflicts and residuals remain visible. A COM-over-support display is only a static hint.
5. **Physics → Flight conditions** selects endpoint positions or initial position/velocity, optional required end velocity, and conservation of angular momentum. Release world pins. The interval must not overlap planted contacts. Incompatible velocity conditions fail with a numerical residual and a suggested condition to release.
6. **Solve** selects iteration/time budgets, important pose frames and optional Rest at end for dynamics correction. It runs in the background. Inspect the status and before/after report; orange COM path is source and green is result. Bodies / forces displays shapes, selected joint axis and actual contact-force arrows.
7. Open the result as a separate scene, compare, save and export. Editing/closing the source invalidates pending/ready results. Cancel preserves the source. Results include model/input identity, engine/settings and metrics in project data; subsequent authoring marks their validation stale.

**Simulate** is a separate Passive/Follow preview. External anchors (preview) explicitly enables legacy world pins/contact welds and reports their forces. Such a preview is not a ground-contact certificate. Passive retains authored bounded internal viscous damping, with no position servo. Coupled passive rotation uses the full implicit integrator; driven optimization uses implicitfast. Legacy anchors select 64 numerical substeps and report that refinement. If another preview diverges it can restart from the original state with a smaller numerical timestep, up to 64 substeps; requested/actual substeps and the retry are reported. Mechanical parameters and authoring settings are preserved. Dynamics correction never creates these anchors and never actuates the free root.

## Model and coordinates

- Internal units are metres, kilograms and seconds, forces N, torques Nm, inertia kg m², angular momentum kg m²/s. Scene positions/shapes are multiplied by metersPerUnit; principal inertia is already SI. Positive uniform static scale is incorporated. Animated scale, shear/nonuniform ancestors and animated translations of non-free rigid segments produce diagnostics.
- Editor and solver share a right-handed +Y-up world. Gravity is (0,-g,0). The infinite plane is at scene ground * metersPerUnit; its local +Z normal is rotated onto +Y.
- Body `b<node ID>`, joint `j<node ID>_...`, site `s<node ID>` names are stable within the compiled model. Physical parents are the nearest physical ancestor. Rest globals determine body offsets/orientations and geoms; helpers retain their animation during reconstruction. Automatic fitting uses reviewed roles or a sufficiently populated suggested major-segment profile rather than fingers/helpers.
- Qt quaternion constructor and MuJoCo qpos both use scalar first (w,x,y,z); project JSON/glTF store x,y,z,w. Rotation velocities/differences use mj_differentiatePos/mj_integratePos, never quaternion component subtraction. Free/ball joints have different qpos/qvel dimensions.
- Undirected rotations use native ball joints. Directed hinges retain the authored rest axis and asymmetric endpoints. Directed swing/twist joints use three rest-axis hinges: twist plus two swing axes. The rectangular Euler swing bounds approximate the editor's circular swing domain and have singularities at 90 degrees; swing coordinates are bounded to ±89.9 degrees. Exact editor-domain deviation is measured separately and prevents solved status when it exceeds the fixed acceptance limit. This limitation is not silently replaced by a symmetric ball cone.
- Capsule inertia is estimated analytically from cylinder and hemisphere masses and the parallel-axis theorem. Custom principal inertia and its bone-local orientation override that estimate. Principal moments must be positive and satisfy triangle inequalities. Estimated geometric mass allocation is an initial guess, not measured human biomechanics.

## Algorithms and limits

Each task owns an immutable RAII mjModel and its own mjData instances. XML parsing/compilation uses an independent mjSpec; the global last-XML API is not used. No native mutable pointer is exposed through Qt/MCP. Model compilation failures retain node-specific diagnostics. CPU timestep is 1 / (source FPS * substeps), independent of rendering.

Whole-body posing uses MuJoCo site/COM Jacobians, damped weighted least squares in generalized tangent coordinates, pose regularization, bounded steps and editor-domain projection. Translation/rotation changes preserve rigid segment lengths. It is a finite-iteration local solver; infeasible is a reported target conflict/budget outcome, not a global impossibility proof.

Flight solves the analytical COM trajectory in SI and translates the complete current mass distribution onto it. Angular correction evaluates changing internal shape velocities, uses the full angular momentum matrix, solves the free-root angular velocity required to preserve initial world angular momentum, and integrates orientation in SO(3). COM correction rotates/recentres the whole current pose, not just a root-position proxy. The report independently samples the baked motion to measure momentum drift. Large/discontinuous shape changes can miss tolerance and remain approximate.

Dynamics correction optimizes bounded internal control knots by deterministic symmetric perturbation shooting. Inverse feedforward estimates required support wrenches and maps them into joint torques. COM/foot/orientation feedback and joint tracking stabilize each trial; feedforward support forces are bookkeeping only and are never applied externally. Actual reactions come from MuJoCo unilateral geom contacts and friction. Native affine actuator velocity bias is integrated implicitly and complete actuator force is limited; free-root DOFs have no actuator. Searching controls, rather than only playing PD targets or invoking inverse dynamics, changes the resulting trajectory. Each trial starts once from the authored initial state and integrates forward without resetting qpos. A separate replay uses saved admissible controls from the same initial state.

Reports must distinguish native forward/inverse consistency, sampled-animation inverse residuals, actual contact/penetration/friction and goal errors, independent replay error and analytical invariants. Small root residuals alone do not certify preservation of poses or contacts. Impact and contact-transition errors are reported separately; tolerances are fixed in PHYSICS_ACCEPTANCE.md. A finite-budget local search may find no acceptable motion, especially on a coarse/imported model. The source and best trial remain independently reviewable. Joint stops use a 4-ms critically damped numerical response (subject to MuJoCo timestep safety); exact editor-domain residuals still gate status.

Results normally bake at an integer multiple of the source rate, up to 240 FPS; dynamics output divides the native simulation rate. Duration and authored contact times are preserved. This retains curved COM and impact motion between source keys. Specify an explicit compatible output FPS when desired. A low-rate legacy flight preview can remain approximate because its interpolated COM exceeds tolerance even if its keys are exact.

The standalone `TricksterPhysicsReplay.exe` reads the exact MJCF, initial qpos/qvel and compressed native controls/trajectory stored in a result. It checks hashes/dimensions, rejects free-root actuators/equality anchors/mocap, sets qpos once, and independently steps the saved controls. Its whole-system impulse check sums each body’s Jacobian COM velocity, orbital plus principal-inertia spin momentum, gravity and actual ground contact wrenches. It does not call the editor evaluator, backend measurement routine or inverse dynamics. The process also reports actuator-limit ratio. No Python is involved.

The report separates native acceleration/inverse consistency from finite impulse balance and source-rate sampled-animation inverse diagnostics. The latter uses the same centered difference interval for source/result and excludes boundary samples; it can have large errors at compliant impacts and is not substituted for the native trajectory validation. No free-root inverse residual is applied as a force. The compact Qt report displays these measurements separately.

## Reproduction

`build.ps1 -QtRoot <Qt SDK>` configures/downloads the pinned official Windows SDK, verifies SHA-256 and copies mujoco.dll beside the native executables. `package.ps1 -NoArchive -OutputDirectory dist/Trickster-physics` includes that DLL and MuJoCo/embedded-dependency notices. For another platform provide an installed MuJoCo 3.3.7 CMake package; those platforms have not been validated here. See third_party/mujoco/UPSTREAM.txt and PHYSICS_MIGRATION.md.

Run `ctest --test-dir build --output-on-failure`, or `build/JesterMuJoCoTests.exe -o artifacts/physics-tools.txt,txt` and `build/TricksterPhysicsUItests.exe -o artifacts/physics-ui.txt,txt`. Repeat the latter with QT_SCALE_FACTOR=1.5. The UI test sizes the client area to physical 1280×720 at both scales. Fixtures and measurements are under examples/physics and artifacts/physics-demo; tests regenerate owned synthetic examples.

Runtime reports identify the actual CPU, logical processors, OS and peak process working set (including previous tasks/Qt, not isolated task memory). Measurements are not a promise for another laptop/GPU. No bitwise cross-platform/version reproducibility claim is made.

Official pinned references: [release](https://github.com/google-deepmind/mujoco/releases/tag/3.3.7), [simulation/thread ownership](https://mujoco.readthedocs.io/en/3.3.7/programming/simulation.html), [API](https://mujoco.readthedocs.io/en/3.3.7/APIreference/APIfunctions.html), [MJCF](https://mujoco.readthedocs.io/en/3.3.7/XMLreference.html), [computation](https://mujoco.readthedocs.io/en/3.3.7/computation/index.html).

## Demonstrations and known restrictions

Open `examples/physics/*-source.trickster` and the matching `*-result.trickster`. Whole-body and COM examples use the full major-segment mannequin. Supported squat/landing deliberately use a documented coarse seven-body, 20-DOF model: the unmoving upper body is lumped into the pelvis, with bilateral thighs/shins/feet. It is not evidence that arbitrary full-body imported landing tasks converge. Both clips keep controlled root-motion corruption, important frames 0/15/30 and one-second duration. Landing begins airborne, has a one-frame authored contact transition, and requests rest at the end. The explicit source substep is 1/1920 s for squat and 1/3840 s for landing (64 / 128 steps per 30-FPS frame) to resolve the impact; masses, geometry, gravity, friction and drive limits remain fixed during search. Solver budgets are 30 iterations / 20 seconds for squat and 30 / 40 seconds for landing. A 1/480-s development run failed the impulse peak gate; that result was not accepted.

The real optional HumanM fixture is tested from native `HumanM_Model.fbx` (58 nodes, 21 bodies, 66 DOF). Its converted walk GLB carries a slightly nonuniform constant animated scale channel differing from rest scale and is diagnosed as unsupported by the rigid model. Its authored animation remains saved/exportable; no scale channel is silently normalized. Native fixture files remain in the ignored user library/artifacts and are not added to the public source examples. Non-Windows builds, arbitrary contact planning and GPU calculations are unverified/outside this stage. Flight invariant correction does not certify that all required internal joint torques are feasible.

See [inherited acceptance definitions](https://github.com/Atmosaero/Trickster/blob/main/docs/PHYSICS_ACCEPTANCE.md), [Jester testing](TESTING.md) and [build instructions](BUILD.md).

### Open dynamics acceptance gate

The fixed inverse-dynamics thresholds also apply to the baked animation. A valid native control rollout does not make the resampled pose derivatives valid. The current squat and landing outputs therefore remain **approximate**: native contact/impulse/goal checks can pass while centered inverse dynamics of baked keys exceeds the force/moment limits, particularly at impacts. Reports keep both measurements and the source-rate before/after values. This stage does not claim completion of the baked-dynamics acceptance gate or equivalence to AutoPhysics. Flight and static posing retain their separately defined validation scope. Double-click a measured frame in the report to inspect it.

Important poses use `frame:weight` entries in the Solve dialog, for example `0:10, 15:5, 30:10`; a plain frame uses weight 5. Reopening preserves priorities, weights and advanced saved settings. Whole-body targets can be added/removed; COM can constrain its horizontal projection or also height. Small principal inertias are edited with 12 decimal places; applying a changed mass retains untouched scalar model values exactly. Source clips remain the place to continue constrained authoring; baked copies clear editing constraints, retain their schedule/report/native replay, and do not provide a certified continuous acceleration representation. The next dynamics target is consistent trajectory/derivative preservation through baking, followed by the same fixed inverse/forward/export checks.

Legacy external-anchor forces are reported in SI after projecting each equality's multipliers through its constraint Jacobian transpose. The report includes per-anchor world forces and moments in the free-root local frame about the root origin, with separate maxima in N and Nm; raw weld quaternion multipliers are not labelled as forces. The held-mass analytic check verifies equilibrium against M g and M g r. This remains an explicitly external-support preview, not a ground-contact certificate.

## Reliability workflow

Choose the interval, important frames and end-rest goal in **Physics > Optimize dynamics**. The persisted **Prepare landing reference** option changes intermediate leg targets around an authored contact; it preserves important poses, initial state, model and contact schedule. It is a local heuristic, not a contact planner. Use explicit substeps for numerical refinement; output FPS does not change the physical timestep during compatible baking.

For an imported clip rejected due to constant scale, use **Physics > Prepare rigid proxy...**. Compare both viewports, choose proxy FPS, preview, then open the measured approximate copy as a new scene. The source remains available. The operation checks a fixed 1-mm world geometry/joint error; animated deformation and nonrigid offsets can still be unsupported. An accepted proxy is not a physical certificate.

Reports show native control, baked kinematics, baked dynamics, represented impulse balance, interval boundary and external validation separately. Double-click a diagnostic row to inspect its frame. Saving retains the report and model/control record. Export feedback retains approximate/stale status and reports additional event samples. Geometry-preserving export alone does not prove dynamics; external validation starts as not checked. See [reliability evidence](PHYSICS_RELIABILITY.md) for reproduction and outstanding acceptance gates.
